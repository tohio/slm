# Architecture

This document describes the SLM pipeline components and their artifact
boundaries for contributors and operators.

![SLM pipeline architecture](architecture.svg)

The SVG is the diagram source and rendered artifact.

## Components

| Component | Ownership | Primary output |
|---|---|---|
| `curator/` | Source loading, filtering, deduplication, blending | `$DATA_DIR/runs/<size>/curated/` |
| `validation/` | Source-aware post-curation validation | `$DATA_DIR/runs/<size>/validated/` |
| `tokenizer/` | BPE tokenizer and chat template | `$DATA_DIR/runs/<size>/tokenizer/` |
| `pretrain/` | Corpus tokenization and base training | `$RESULTS_DIR/runs/<size>/pretrain/final` |
| `finetune/` | Instruct, code, and optional code-completion SFT | `$RESULTS_DIR/runs/<size>/sft_*/final` |
| `alignment/` | Chat preference alignment with DPO | `$RESULTS_DIR/runs/<size>/dpo_chat/final` |
| `eval/` | Benchmark and behavior checks | `$RESULTS_DIR/runs/<size>/eval/` |
| `export/` | Native Transformers package and Hub publication | `$EXPORTS_DIR/<size>/<variant>/` |
| `inference/`, `serve/` | Local generation and vLLM serving | Generated responses and API service |

Shared contracts live under `config/`. Hardware-aware training configuration
is generated by `config_gen/`.

## Model Lineage

```text
pretrain/final
  └── sft_instruct/final
      ├── dpo_chat/final
      └── sft_code/final
          └── sft_code_completion/final (optional)
```

The chat and code branches share the same instruct parent. DPO is not applied
to the code branch in this repository.

## Checkpoint and Publication Boundary

Training checkpoints use the in-repository `SLMConfig` and
`SLMForCausalLM`. They are local pipeline artifacts and require the repository
implementation.

Export converts a validated checkpoint to the equivalent native Transformers
`LlamaForCausalLM` format. Published packages contain no executable model code,
no `auto_map`, and load with `trust_remote_code=False`.

## Data and Artifact Identity

Reusable data artifacts are scoped by model size and an opaque `RUN_ID`.
Stage manifests bind derived outputs to their inputs and configuration.
Training and post-training checkpoints copy the relevant data manifest into
their final directory so export can produce model-card provenance without
guessing.
